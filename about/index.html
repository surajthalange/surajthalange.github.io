How I test

  • Unit tests first for logic. Game engines, grade presenters, inclusion rules and settings models are pure classes with tests written before the implementation.
  • Behat for what users touch. Every page a learner, teacher or administrator interacts with has a scenario, including the failure paths (no capability, hidden grade, empty scope).
  • The full matrix in CI. Every supported Moodle branch, the PHP versions it supports, and both PostgreSQL and MariaDB, because engine differences bite when a plugin ships a schema.
  • Reviewer's eye. I review my own plugins against the Marketplace checklist before submission: security, privacy, strings, versions, documentation. It is why the first review came back with no blockers and the plugin went straight into the directory.
