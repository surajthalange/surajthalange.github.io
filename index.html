How I work

Small scope, written down, tested, handed over

  1. Scope in writing

    A short brief with what is in, what is out, and how we will know it is done. You approve it before any work starts.

  2. Build on a staging copy

    Nothing touches production until you have clicked through it. Changes ship as versioned plugins, never edits to core.

  3. Tests and CI

    PHPUnit and Behat for the behaviour that matters, run in GitHub Actions on every change, across the Moodle and PHP versions you run.

  4. Handover you can keep

    Runbooks, admin guides and a reset script for training, so the platform does not depend on me being available.

Delivery and leadership

Someone has to own the plan, not just the code

On larger platforms I am the technical project manager as well as a developer: requirements and estimates, sprint plans, coordinating development, QA, UI/UX and infrastructure, then UAT, deployment and the month after it.

How I run a delivery

Teams, not just tickets

Coordinating development, QA, UI/UX and infrastructure so the platform is ready at the same time as the code is.

Deployment that is rehearsed

A written release sequence, a backup taken first, a tested rollback, and a window agreed with everyone it touches.

Every phase ends in a document

BRD, estimate, delivery note per milestone, acceptance record, runbook. Status and risk in writing, not only in standups.
